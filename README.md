# Tema 1 · Digitalización — Web para GitHub Pages

Web estática multipágina basada en el Tema 1 del PDF aportado: **“Digitalización. Creación de entornos IT y OT”**.

## Archivos
- `index.html`: portada y mapa del tema.
- `digitalizacion.html`: definición, motivos, aplicaciones y cambios empresariales.
- `it-ot.html`: tecnologías IT/OT, departamentos y herramientas.
- `evolucion.html`: evolución IT-OT, beneficios, riesgos y caso Repsol.
- `actividades.html`: actividades de repaso y aplicación.
- `reto.html`: reto profesional de la papelería “Tu Rincón”.
- `styles.css`: diseño responsive.
- `app.js`: menú móvil, modo oscuro y búsqueda local.

## Publicarlo en GitHub Pages
1. Crea un repositorio en GitHub.
2. Sube todos los archivos de esta carpeta a la raíz del repositorio.
3. Ve a **Settings → Pages**.
4. En **Build and deployment**, selecciona **Deploy from a branch**.
5. Selecciona la rama principal y la carpeta `/ (root)`.
6. Guarda y espera a que GitHub publique la web.

No necesita servidor ni framework: funciona como HTML/CSS/JS estático.


## Juegos educativos y puntuación

Se ha añadido `juegos.html` con tres juegos:
- **Quiz de digitalización**: preguntas tipo test.
- **¿IT, OT o ambas?**: clasifica tecnologías y herramientas.
- **Reto relámpago**: verdadero/falso con 45 segundos.

Las puntuaciones se guardan en el navegador y se muestra un Top 3 local. Para que el Top 3 sea compartido entre todos los visitantes, configura la base de datos gratuita de Supabase como se explica a continuación.

### Activar un Top 3 global con Supabase

GitHub Pages solo sirve archivos estáticos; no proporciona una base de datos ni un servidor propio. Supabase ofrece una base de datos PostgreSQL con API que puede consultarse desde la web.

1. Crea un proyecto en [Supabase](https://supabase.com/).
2. En **SQL Editor**, ejecuta este SQL:

```sql
create table if not exists public.scores (
  id bigint generated by default as identity primary key,
  name text not null check (char_length(name) between 1 and 18),
  score integer not null check (score >= 0 and score <= 10000),
  game text not null check (char_length(game) <= 60),
  created_at timestamptz not null default now()
);

alter table public.scores enable row level security;
grant select, insert on public.scores to anon;
grant usage, select on sequence public.scores_id_seq to anon;

create policy "Puntuaciones visibles para todos"
on public.scores for select
to anon
using (true);

create policy "Visitantes pueden registrar puntuaciones"
on public.scores for insert
to anon
with check (
  char_length(name) between 1 and 18
  and score between 0 and 10000
  and char_length(game) <= 60
);
```

3. En los ajustes del proyecto, copia la **Project URL** y la clave pública **anon** (o publishable key compatible con la API REST).
4. Abre `supabase-config.js` y reemplaza `https://TU_PROYECTO.supabase.co` y `TU_CLAVE_ANON_PUBLICA` por tus valores.
5. Sube todos los archivos al repositorio. Cuando publiques o actualices GitHub Pages, el Top 3 global aparecerá automáticamente.

**Importante:** nunca pongas la clave `service_role` en una web pública. La clave `anon` está pensada para uso público y las políticas RLS limitan las operaciones permitidas, pero este ejemplo no puede verificar que una puntuación sea legítima: una persona podría enviar puntuaciones falsas. Si necesitas una clasificación competitiva resistente a trampas, hay que añadir un backend o una función de servidor que valide las partidas. Si no configuras Supabase, los juegos siguen funcionando y el Top 3 se almacena localmente en cada navegador.

## Publicar en GitHub Pages

Mantén todos los archivos en la raíz del repositorio y activa **Settings → Pages → Deploy from a branch → rama principal → /(root)**. `index.html` es la portada. No se necesita instalar un framework.
